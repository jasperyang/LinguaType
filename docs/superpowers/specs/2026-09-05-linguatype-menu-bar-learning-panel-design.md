# LinguaType 菜单栏与语言学习浮窗设计

日期：2026-09-05

## 1. 目标

把当前右上角的“字”悬浮方块替换为真正的 macOS 菜单栏入口，并把语言学习浮窗升级为稳定、清晰的三语学习卡片。每次提交中文文本后，界面固定显示法语、英语、日语翻译，并解释最多三个有学习价值的关键词。

完整输入句子不得发送给第三方词典。第三方请求只能包含单个规范化关键词；整句翻译、释义转中文和上下文匹配都在本机完成。

## 2. 已确认的产品决策

- 固定显示法语、英语、日语，不提供目标语言轮换。
- 浮窗采用“分层纵向卡片”布局，宽度约 520 px。
- 每次解释最多三个关键词；每个词条提供较丰富的中文说明。
- 英语和法语显示 IPA；日语显示假名和罗马音。
- 菜单栏使用单色“A·あ”字标，不再显示屏幕右上角的“字”窗口。
- 采用多词典直连和本地缓存；不接入联网 AI，也不要求用户配置 API 密钥。
- 浮窗自动显示 12 秒；鼠标进入后暂停倒计时，隐藏后可以从菜单栏重新打开最后结果。

## 3. 不在本次范围内

- 不修复或重新签名无法在 macOS 26 中注册的 InputMethodKit 输入源。
- 不增加第四种目标语言，也不提供语言排序或开关。
- 不上传整句以换取 AI 生成的解释。
- 不增加发音音频、单词收藏、记忆曲线、测验或账户同步。
- 不搭建 LinguaType 自有后端服务。

## 4. 用户体验

### 4.1 菜单栏入口

应用通过 `NSStatusItem` 创建一个系统菜单栏项目，长度使用方形状态项宽度。按钮图像为 18×18 pt 的单色模板图，内容是“A·あ”字标；模板图自动适应浅色、深色和选中状态。辅助功能名称为“LinguaType 语言学习”，工具提示为“点击显示学习卡片，右键打开设置”。

- 左键：显示或隐藏最后一次学习浮窗。
- 右键：打开设置菜单。
- 菜单包含：启用/暂停语言学习、启用/暂停联网查词、语言模型状态、清除词典缓存、隐私说明、退出。
- 旧 `AnchorPanel` 和它的“字”按钮被彻底移除，应用不再创建独立的右上角入口窗口。

### 4.2 浮窗布局

浮窗保持 `NSPanel` 的非激活特性，不夺取当前文本输入焦点。默认宽度为 520 px，贴近当前输入光标出现；下方空间不足时翻到光标上方，水平方向始终限制在当前屏幕可见区域内。

内容从上到下为：

1. 标题区：`LINGUATYPE · 语言学习` 和轻量状态指示。
2. 原句区：显示本次中文原句，最多两行，超出部分尾部截断。
3. 整句翻译区：固定三行法语、英语、日语，每行有国旗、语言名和译文。
4. 词汇区：最多三张纵向词汇卡。

每张词汇卡显示：

- 中文词和词性。
- 两到三个简短、互不重复的中文义项。
- 在本地判断置信度足够时显示“本句含义”；置信度不足时不显示该标签，不猜测。
- 法语词和 IPA。
- 英语词和 IPA。
- 日语词、假名和罗马音。

浮窗高度根据内容增长，但不得超过当前屏幕可见高度的 60%，且不得超过 560 px。超过上限时仅词汇区滚动，标题、原句和三语整句保持可见。鼠标可以滚动词汇区，但点击或滚动不会把键盘焦点从正在输入的应用切走。

### 4.3 展示时序

提交中文文本后维持现有 280 ms 防抖：

1. 立即显示加载态和原句。
2. 法、英、日整句翻译按队列逐行更新。
3. 本地提取关键词后，先显示词卡骨架，再在本机把每个中文关键词翻译成对应的法语、英语和日语查询词。
4. 每个词典结果独立到达、独立更新，不等待所有词完成。
5. 第一条整句译文或明确错误状态出现时开始 12 秒自动隐藏计时；鼠标进入浮窗暂停，移出后继续。
6. 自动隐藏只隐藏窗口，不丢弃结果；左键菜单栏图标可重新打开。

## 5. 组件边界

### 5.1 `StatusBarController`

只负责 `NSStatusItem`、左右键分派、菜单内容和菜单状态刷新。它不读取翻译结果，也不发起网络请求。左键调用 `togglePanel`，右键弹出 `NSMenu`。

### 5.2 `TranslationPipeline`

从当前 `LearningCoordinator` 中提取 Apple Translation 调度职责，串行管理所有 `TranslationSession`。队列优先级依次为整句翻译、关键词翻译、词典释义转中文；整句固定目标顺序为法语、英语、日语。每种语言独立保存加载、成功和失败状态，单项失败不会终止队列。

### 5.3 `VocabularyExtractor`

只在本机处理中文原句。它使用 `NLTokenizer` 和词性信息生成候选词，过滤标点、数字、停用词、单字虚词及重复词。排序优先级依次为：内容词、二至四字词、在当前句中有明确词性、近期未反复展示。最终返回一到三个词，并保留在原句中的顺序。

### 5.4 `DictionaryService`

通过统一协议协调四个提供方适配器，输入是单个规范化词和语言，输出是统一的 `DictionaryEntry`。适配器之间互不依赖，可以单独测试和替换。每个中文关键词直接查询中文词典；它在本机得到的法、英、日查询词分别进入对应外语词典。词典请求最多并发四个，同一提供方最多并发两个，避免一次三词查询造成突发流量。

- `ChineseWiktionaryAdapter`：查询中文 Wiktionary 的 MediaWiki API，读取中文词性和义项。
- `FrenchWiktionaryAdapter`：查询法语 Wiktionary 的 MediaWiki API，读取词性、IPA 和义项。
- `EnglishDictionaryAdapter`：查询 Free Dictionary API，读取词性、IPA 和多个义项。
- `JapaneseJotobaAdapter`：调用 Jotoba 的 `/api/search/words`，读取 JMdict 派生的汉字、假名、词性、多个义项和可用的音调信息。

所有外语义项通过本机 Apple Translation 转为简体中文。日语罗马音从假名在本机转换生成，不单独发起网络请求。

提供方的返回内容在界面中以摘要方式呈现，并在隐私说明中标注 Wiktionary、Free Dictionary API、Jotoba 及 JMdict 来源，遵守各自的署名和许可要求。

### 5.5 `SenseMatcher`

使用本机已有信息选择“本句含义”：中文词性、Apple Translation 给出的三个目标词，以及词典返回的词性和义项。它只做确定性打分，不调用生成模型。当第一名与第二名分数差不足阈值时，返回无匹配，界面不显示“本句含义”。

### 5.6 `DictionaryCache`

缓存键包含提供方、语言、规范化词和数据结构版本。成功结果保存 30 天；无结果和短暂失败保存 10 分钟。清除缓存菜单项只删除 LinguaType 的词典缓存，不碰学习曝光记录或其他用户文件。

### 5.7 `LearningPresentationModel`

把整句翻译、关键词、词典结果和加载状态合并成不可变展示状态，交给 `TranslationPanel` 渲染。视图不负责解析、翻译或网络重试。

## 6. 数据模型

核心展示模型如下：

```swift
struct LearningDisplayState: Equatable {
    var sourcePhrase: String
    var phraseTranslations: [PhraseTranslation]
    var vocabularyCards: [VocabularyCard]
    var phase: LoadingPhase
}

struct PhraseTranslation: Equatable {
    var language: LearningLanguage
    var text: String?
    var status: RowStatus
}

struct VocabularyCard: Equatable {
    var source: String
    var partOfSpeech: String?
    var chineseSenses: [String]
    var contextualSense: String?
    var terms: [LocalizedTerm]
    var status: CardStatus
}

struct LocalizedTerm: Equatable {
    var language: LearningLanguage
    var term: String
    var ipa: String?
    var kana: String?
    var romanization: String?
}
```

`LearningLanguage` 在本次只允许 `fr`、`en`、`ja`，并始终按该顺序展示。缺失字段使用 `nil`，不得用猜测值或占位文本冒充词典数据。

## 7. 网络与隐私约束

- 外发请求的查询词必须通过独立的 `DictionaryQuery` 类型构造；该类型不能持有原句。
- 查询词去除首尾空白和标点，长度限制为 32 个 Unicode 字符。
- 请求体或 URL 只能包含一个查询词、目标语言和提供方规定的固定参数。
- 不发送输入应用名称、窗口标题、光标位置、设备标识或学习曝光历史。
- 日志只记录提供方、状态码、耗时和缓存命中，不记录原句或查询词。
- 每个请求超时 4 秒；只对连接中断、超时和 5xx 重试一次，并使用短延迟抖动。4xx 和“无词条”不重试。
- “暂停联网查词”关闭后不得产生任何词典网络请求；已有缓存仍可使用。
- 应用菜单中的隐私说明明确列出四个提供方，并提供相应来源与许可链接。

## 8. 模型状态与失败降级

Apple Translation 任务串行执行，避免法、英、日模型同时准备。菜单显示每种语言模型的状态：可用、准备中、需要下载或不可用。

- 某个整句翻译失败：该语言行显示明确原因，其他语言继续。
- 某个词典超时：该词卡对应语言显示“词典暂时不可用”，其他内容继续。
- 所有词典均无结果：保留整句翻译，词卡显示“暂无详细词典释义”。
- 外语释义无法本地翻成中文：不显示未经翻译的长段落，只保留词、词性和读音。
- 日语罗马音生成失败：仍显示日文和假名。
- 断网：优先展示缓存；未缓存词条标注“离线，暂无词典内容”。
- 完整句子绝不作为错误恢复手段发送给任何在线服务。

## 9. 测试设计

### 9.1 单元测试

- 关键词提取：停用词、标点、重复词、单字虚词、长句和不足三个候选词。
- 三语固定顺序和单行失败隔离。
- Apple Translation 的整句、关键词和释义任务优先级，保证词典工作不会阻塞新句子的三语翻译。
- 四个词典适配器使用保存的响应样本测试解析，不让测试依赖实时网络。
- IPA、假名、罗马音和多个义项的缺失字段处理。
- `SenseMatcher` 的高置信度选择与低置信度放弃。
- 缓存命中、30 天过期、10 分钟负缓存和结构版本失效。
- 12 秒倒计时、鼠标悬停暂停、移出继续和重新打开。

### 9.2 隐私契约测试

使用自定义 `URLProtocol` 拦截全部请求，并断言：

- 每个请求只包含一个规范化词。
- URL、请求体和请求头都不包含完整原句。
- 暂停联网查词时请求数为零。
- 日志输出不包含原句和查询词。

### 9.3 界面与几何测试

- 浮窗位于光标附近且完整落在当前屏幕可见区域。
- 下方空间不足时正确翻到上方。
- 高度不超过可见屏幕的 60% 和 560 px，并只滚动词汇区。
- 菜单栏按钮具备正确的辅助功能名称和工具提示。
- 应用不再创建 `AnchorPanel`。

### 9.4 真实端到端验收

在 TextEdit 中用系统拼音输入一段包含至少三个内容词的中文句子，验证：

1. 280 ms 防抖后浮窗出现且不夺取输入焦点。
2. 法、英、日三行均出现并能独立完成或失败。
3. 展示一到三张词卡，包含中文义项及相应读音字段。
4. 词汇区可滚动，标题和整句区域保持固定。
5. 12 秒后自动隐藏，鼠标悬停可暂停，菜单栏左键可重新打开。
6. 菜单栏只显示“A·あ”，屏幕右上角不存在“字”方块。
7. 断网、模型未准备、多屏幕和词典无结果场景均按降级规则工作。

## 10. 完成标准

当所有单元测试、隐私契约测试和真实 TextEdit 验收均通过，且没有发现完整原句外发、输入焦点被抢走、窗口越界或旧锚点残留时，本功能才算完成。仅编译成功或只看到菜单栏图标不视为完成。
